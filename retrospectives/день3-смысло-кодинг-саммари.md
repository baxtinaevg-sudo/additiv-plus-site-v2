# 1. Структурное саммари по блокам

## Блок 1: GitHub и откаты

### Три ключевых понятия

| Термин | Что означает | Аналогия |
|---|---|---|
| **Репозиторий** | Папка проекта в облаке (GitHub) | Облачное хранилище кода |
| **Commit** | Точка сохранения (snapshot) | «Сохранить игру» |
| **Push** | Отправка commit в облако | Загрузить сохранение в облако |

### Как работает цикл

1. Создать приватный репозиторий на GitHub: «создай приватный репозиторий на GitHub для текущего проекта, назови его вот так»
2. Добавить все файлы, кроме `.env`: «добавь все файлы, кроме .env»
3. Сделать commit: «сделай commit с сообщением <текст>»
4. Запушить: «сделай push»

### Откат (точка возврата)

Когда код сломался:
- Сказать Claude: «верни как было вчера» / «откатись на предыдущую версию»
- Или через GitHub: открыть список коммитов, выбрать нужный, вернуться
- Занимает 3 секунды

### Правила безопасности

1. `.env` НИКОГДА не отправлять в git - всегда в `.gitignore`
2. `git add` поимённо, никогда `git add .` или `git add -A`
3. Commit после каждой фазы (минимум раз в день)
4. Секреты лежат в `.env` и в `.gitignore` обязательно прописано

## Блок 2: Деплой: Vercel / Railway / Amvera

### 4 варианта деплоя

| Платформа | Для кого | Плюсы | Минусы |
|---|---|---|---|
| **Vercel** | Зарубежные проекты, быстрые MVP | Бесплатный план, простой, быстрый | Не для российских пользователей при наличии ПД |
| **Railway** | Более сложные проекты с бэкендом и БД | Полноценный бэкенд, удобный интерфейс | Платный после пробного периода |
| **Amvera** | Российский аналог Railway | Российские карты оплаты, проксирование LLM API, git-push деплой | Для небольших проектов |
| **Выделенный сервер (Яндекс и др.)** | Большие проекты с высокой нагрузкой | Полный контроль, масштабируемость | Сложно, дорого (от 15-18 тыс. руб./мес.) |

### Как деплоить через Vercel

1. Первый раз: сказать Claude «отправь на Vercel» - он установит Vercel CLI
2. Подключиться к учётной записи Vercel
3. Каждый следующий проект деплоится автоматически

### Как деплоить через Amvera

1. Код хранится в GitHub-репозитории
2. Amvera автоматически подтягивает обновления из репозитория
3. При push в репозиторий сайт обновляется сам

### Важное про российские данные

- Если собираешь e-mail, телефоны, имена российских пользователей - обязан хранить на российских серверах
- Нужно уведомить Роскомнадзор о том, что ты обработчик персональных данных
- Штрафы за нарушение
- Для MVP без хранения персональных данных - можно Vercel

## Блок 3: Chrome Claude и связка с Claude Code

### Как спикер работал с двумя моделями

- **Claude (в VS Code)** - основной кодер, но часто зависал в прямом эфире
- **ChatGPT (отдельная вкладка)** - запасной вариант, когда Claude зависал

### Приём «Оркестратор + Исполнитель»

- **Оркестратор (один чат)** - читает план, пишет промт для каждой фазы
- **Исполнитель (новый чат)** - получает готовый промт, реализует фазу
- Результат исполнителя возвращается в оркестратор для проверки

### Почему это важно для экономии токенов

- Каждое сообщение в чате добавляет ВСЮ историю в контекстное окно
- ChatGPT сожрал 77K токенов за пару итераций (30% контекстного окна)
- Новый чат = чистое контекстное окно = огромная экономия
- При правильной методологии подписки за $200 хватает на месяц; без неё - на день

### DeepSeek как альтернатива

- DeepSeek V4 Pro работает на 90% от уровня Claude Opus
- В 5 раз дешевле Sonnet 4.5
- Хорошо пишет код, поддерживает русский язык
- Если Claude не пробивается - переходи на DeepSeek

## Блок 4: База данных

### Локальная vs серверная

| Этап | Где работает | Что делаешь |
|---|---|---|
| Разработка | Локальная БД (на компьютере) | Тестируешь, правишь |
| Деплой | Серверная БД (Amvera, Railway, Яндекс) | Продакшн |

### Как подключить

1. Сказать Claude: «мне нужна база данных для проекта, подскажи какой лучше»
2. Он сам посоветует (MySQL, PostgreSQL, SQLite и т.д.) - он знает лучше
3. Для подключения к удалённой БД: нужна строка «ссылка, логин, пароль»
4. Если не знаешь где взять: Claude сам зайдёт в панель хостинга и найдёт

### Защита от удаления данных

1. **Создать пользователя только для чтения**: «создай пользователя БД только с правами чтения, без возможности редактировать и удалять»
2. **Бэкапы**: настроить автоматические бэкапы (каждые 2 часа, каждый час, или раз в день)
3. **Обезличивание данных**: AI работает с ID клиентов, а не с реальными именами/email - парсер подменяет персональные данные

### Советы для работы через VS Code

- Claude работает с БД так же, как со всем остальным
- Даёшь задачу - он делает
- Проблем нет, если формулировать чётко

## Блок 7: Методология проектов (полная архитектура)

### 6-шаговая система (для эфира)

```
1. RESEARCH  - Исследование идеи (кто решал, как, что работает)
2. PLAN      - План с фазами и чекбоксами
3. CODE      - Реализация по одной фазе за раз
4. REVIEW    - 10 причин почему не залетит
5. COMMIT    - Сохранение в GitHub
6. DEPLOY    - Отправка в интернет
```

### Полная архитектура для больших проектов

```
Идея (папка с ресерчем)
  -> Архитектура (чертёж: стек, структура папок, БД)
    -> Код (по фазам, каждая с проверкой)
      -> Бизнес (маркетинг, продажи, финансы)
        -> Клон (второй мозг, триггеры)
          -> Триггеры (100 агентов работают каждый день)
            -> Я-Компания (один человек = тысяча сотрудников)
```

### Ключевые принципы

1. **Сначала ресерч, потом код** - не пиши из головы, найди кто уже решал
2. **1 промт = 1 фаза** - никогда не говори «сделай всё»
3. **Валидировать каждую итерацию** - проверять что AI не нагаллюцинировал
4. **Security review после каждой фазы** - проверка на безопасность
5. **Commit после каждой фазы** - точка возврата
6. **Оркестратор в отдельном чате** - экономия токенов

### Что такое «Я-Компания»

Концепция, к которой спикер стремится к концу 2026 года:
- Один человек + AI = полноценная компания
- Сейчас: ~10 триггеров = 10 нанятых сотрудников
- К лету: 100 триггеров
- К концу года: 1000 триггеров = «Я-тысяча»

# 4. Q&A участников

### Q: Как работать с MySQL через VS Code?
**A:** Нет никакой проблемы. Ты говоришь «надо делать» - он делает. Также работает, как со всем остальным. Если будет более глубокий вопрос, в чём конкретно проблема заключается - опишите.

### Q: GPT за 20 баксов хватит?
**A:** Ну, наверное, чуть-чуть пробовать хватит. Большое что-то сделать невозможно за 20 баксов.

### Q: Что такое валидация идеи?
**A:** Это подтверждение жизнеспособности, проверка на жизнеспособность. В том числе подтверждение того, что это точно то, что ты хочешь. Часто AI галлюцинирует, и если не делать проверку, он тебе выдаст кучу лишнего. Его задача отдавать вам больше букв, чтобы вы за эти буквы заплатили.

### Q: Что такое commit?
**A:** Commit - это сохранение. Типа условно можно было сказать «сохранить», а мы говорим «commit» - типа зафиксируй наши изменения. Когда в каждом чате фазу сделали - говоришь «заcommitь изменения».

### Q: Можно код AI-сметчика на GitHub выкатить?
**A:** Да, вообще без проблем. Ничего, все можно.

### Q: Как сказать Claude, чтобы он не удалил базу данных?
**A:** Первое - создай пользователя БД только с правами чтения, без возможности редактировать и удалять. Второе - обязательно делай бэкапы (каждые 2 часа или раз в день). Если что-то произошло - откатываешь бэкап.

### 2. Метод оркестратора

```
## Оркестратор для больших фич
- Оркестратор (один чат) читает план и пишет промт для каждой фазы
```
