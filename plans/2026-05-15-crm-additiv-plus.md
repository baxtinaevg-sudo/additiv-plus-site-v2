# План: CRM/ERP для Аддитив Плюс

**Дата создания:** 2026-05-15
**Статус:** В разработке

---

## Цель

Создать модульную CRM/ERP-систему для Аддитив Плюс, которая объединит все отделы компании: продажи, бухгалтерию, лабораторию, логистику, тех.поддержку и IT. Система заменит ручное ведение клиентов и обеспечит прозрачность воронки, контроль сделок и аналитику для руководства.

**Контекст:** Сейчас данные в 1С (доступа пока нет). CRM начинает работу с симуляцией данных через JSON. Когда появится доступ к 1С - подключим интеграцию.

**Пользователи:** 5-10 одновременных (менеджеры продаж, руководство, бухгалтерия, лаборатория, логистика, тех.поддержка). Руководство также заходит с мобильных.

---

## Гипотезы

1. **Прозрачность воронки.** CRM сделает воронку видимой для руководства в реальном времени - без ожидания отчётов от менеджеров.
2. **Модульность = скорость внедрения.** Внедрение по отделам (продажи -> бухгалтерия -> лаборатория) снизит нагрузку на команду и позволит учиться на ходу.
3. **Frontend-MVP достаточен для старта.** JSON-данные + localStorage позволяют начать работу без бэкенда. Когда будет 1С - перепишем слой данных.
4. **Единый стиль = доверие.** Корпоративный дизайн сайта (beige, champagne, graphite) перенесён в CRM - сотрудники сразу чувствуют «свою» систему.

## Технические решения

### Стек

| Слой | Технология | Почему |
|---|---|---|
| Фронтенд | Vue 3 + Vite + Tailwind CSS | Тот же стек, что и на сайте. Команда знакома. |
| Шрифты | Outfit (body) + Cormorant Garamond (заголовки) | Единый бренд |
| Цвета | beige `#F7F5F0`, graphite `#1A1917`, champagne `#B8A080`, muted `#9A958D` | С сайта |
| Данные (MVP) | JSON-файлы + localStorage | Симуляция 1С |
| Бэкенд (Фаза 4) | Node.js + Express + SQLite | Лёгкий, файловый, не требует отдельного сервера БД |
| Хранение | Папка `crm/` в репозитории | Рядом с сайтом, но отдельное приложение |

### Архитектура модулей

```
Карточка клиента (ядро)
├── Сделка (продажи)
│   ├── Этапы воронки: Лид → Квалификация → Предложение → Переговоры → Закрытие
│   ├── Сумма, продукты, вероятность
│   └── Ответственный менеджер
├── Счёт/Оплата (бухгалтерия)
│   ├── Реквизиты, номер, дата, сумма
│   ├── Статус: черновик → отправлен → оплачен
│   └── Привязка к сделке
├── Заявка в лабораторию (R&D)
│   ├── Тип: подбор рецептуры / тестирование / анализ
│   ├── Статус: новая → в работе → готово → передано клиенту
│   └── Результаты, протоколы
├── Отгрузка (логистика)
│   ├── Товар, количество, дата, адрес
│   ├── Статус: планируется → в пути → доставлено
│   └── Трекинг
└── Тикет (тех.поддержка)
    ├── Тема, описание, приоритет
    ├── Статус: открыт → в работе → решён → закрыт
    └── История переписки
```

### Ролевая модель

| Роль | Права доступа |
|---|---|
| **Админ** | Всё + управление пользователями + настройки системы |
| **Руководитель** | Все данные всех отделов, дашборды, отчёты, аналитика |
| **Менеджер продаж** | Свои клиенты и сделки + общая база контактов (только чтение чужих) |
| **Бухгалтер** | Счета, оплаты, реквизиты всех клиентов |
| **Лаборант** | Заявки на тесты, результаты, протоколы |
| **Логист** | Отгрузки, доставка, складские остатки |
| **Тех.поддержка** | Тикеты клиентов, история обращений |

### Адаптивность

- **Десктоп** - полное рабочее место для всех ролей
- **Мобильная** - упрощённый интерфейс для руководства (дашборды, уведомления, ключевые метрики)

## Последовательность реализации

### Фаза 1: Ядро + Продажи [ ]

**Срок:** 2 недели
**Цель:** Рабочая CRM для отдела продаж с симуляцией данных

**Задачи:**

- [ ] Инициализация проекта `crm/` (Vite + Vue 3 + Tailwind, конфиг цвета/шрифты)
- [ ] Макет приложения (sidebar навигация, хедер с пользователем, основная область)
- [ ] Авторизация (упрощённая: выбор пользователя из списка, без пароля для MVP)
- [ ] Карточка клиента
  - [ ] Форма: название, ИНН, направление (ССС/ЛКМ/Пластмассы/Каучук), контакты, статус, заметки
  - [ ] Список клиентов с фильтрами и поиском
  - [ ] Привязка к ответственному менеджеру
- [ ] Воронка сделок (Kanban-доска)
  - [ ] Этапы: Лид → Квалификация → Предложение → Переговоры → Закрытие (успех/провал)
  - [ ] Перетаскивание карточек между этапами
  - [ ] Карточка сделки: сумма, продукты, вероятность, сроки, заметки
  - [ ] Привязка к клиенту и менеджеру
- [ ] История взаимодействий
  - [ ] Типы: звонок, встреча, email, заметка
  - [ ] Дата, описание, результат
  - [ ] Привязка к клиенту и/или сделке
- [ ] Задачи и напоминания
  - [ ] Создание задачи с дедлайном
  - [ ] Привязка к клиенту/сделке
  - [ ] Список задач пользователя (сегодня, просрочено, ближайшие)
- [ ] Дашборд руководителя
  - [ ] Воронка в цифрах (количество и сумма по этапам)
  - [ ] Активность менеджеров
  - [ ] Просроченные задачи
  - [ ] Конверсия по этапам
- [ ] JSON-данные (заглушка)
  - [ ] 10-15 тестовых клиентов из реальных сегментов (Кнауф, Старатели, Основит и т.д.)
  - [ ] 20-30 тестовых сделок в разных этапах
  - [ ] 5 тестовых пользователей с разными ролями

**Критерий «сделано»:** Менеджер может завести клиента, создать сделку, двигать по воронке, добавлять контакты и задачи. Руководитель видит дашборд.

**Deliverable:** Рабочая папка `crm/` с `npm run dev` и работающим приложением.

### Фаза 2: Бухгалтерия + Лаборатория [ ]

**Срок:** 1-2 недели
**Цель:** Подключить бухгалтерию и лабораторию к единой системе

**Задачи:**

- [ ] Модуль «Счета и оплаты»
  - [ ] Создание счёта из сделки (автозаполнение)
  - [ ] Реквизиты клиента (автозаполнение из карточки)
  - [ ] Статусы: черновик → отправлен → оплачен → просрочен
  - [ ] Список счетов с фильтрами (по статусу, дате, клиенту)
  - [ ] Роль «Бухгалтер» - доступ ко всем счетам
- [ ] Модуль «Лаборатория»
  - [ ] Создание заявки из сделки или отдельно
  - [ ] Типы: подбор рецептуры / тестирование / анализ качества
  - [ ] Статусы: новая → принята → в работе → готово → передано клиенту
  - [ ] Результаты: текстовые заметки, файлы (MVP - ссылки)
  - [ ] Роль «Лаборант» - свои заявки
- [ ] Обновление карточки клиента
  - [ ] Вкладки: Сделки | Счета | Заявки | История
  - [ ] Кросс-ссылки между модулями

**Критерий «сделано»:** Бухгалтер видит все счета. Лаборант видит свои заявки. Всё привязано к карточке клиента.

**Срок:** 1-2 недели
**Цель:** Завершить модульную структуру

**Задачи:**

- [ ] Модуль «Отгрузки»

  - [ ] Роль «Тех.поддержка» - все тикеты

  - [ ] Адаптивная вёрстка ключевых экранов
  - [ ] Дашборд, уведомления, список задач

**Критерий «сделано»:** Все 6 модулей работают. Руководство заходит с телефона.

## Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| JSON-данные станут узким местом (потеря, конфликт) | Средняя | Среднее | Фаза 4 как можно скорее; регулярный экспорт |
| Сопротивление команды (не хотят новую систему) | Средняя | Высокое | Внедрять по отделам, обучать на каждом этапе |
| Нет доступа к 1С долго | Высокая | Низкое | MVP на JSON достаточен для старта |
| Перегрузка фичами | Высокая | Среднее | Строго по фазам, не добавлять вне плана |
