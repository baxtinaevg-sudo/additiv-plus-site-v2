# 🔍 research-first.md — Исследование перед кодом

> Ментальная модель: сначала понимаешь, потом планируешь, потом пишешь.

## Проблема

Скачок в код без понимания контекста приводит к:
- Переделкам (не учёл существующую структуру)
- Дублированию (не нашёл уже готовое решение в проекте)
- Поломке смежных компонентов (не проверил зависимости)
- Трата токенов на «зондирование» кода методом тыка

## Модель: Research → Plan → Code

### Фаза 1: Исследование (Research)

**Обязательные действия перед любой задачей на код:**

1. Прочитать `CLAUDE.md` - правила проекта, стек, структура
2. Найти затронутые файлы через `list_files`, `search_files`, `read_file`
3. Понять текущую архитектуру в зоне изменения
4. Проверить `plans/` на наличие связанного плана
5. Проверить `ai-clone/feedback/` на релевантные правила

**Критерий готовности:** можешь назвать минимум 3 файла, которые затронет задача, и explain почему.

Если не можешь - ты ещё не готов, продолжай исследовать.

### Фаза 2: Архитектура (Plan)

1. Сформулировать цель (что делаем и зачем)
2. Перечислить затронутые файлы с типом изменения (создать/обновить)
3. Описать риски (что может сломаться)
4. Определить последовательность действий

**Правило:** если задача > 1 часа - оформить план в `plans/`.

### Фаза 3: Реализация (Code)

Только теперь пишем код. Имея на руках:
- Понимание контекста (из фазы 1)
- Чёткий план (из фазы 2)
- Список файлов для изменения

## Красные флаги

- Пишешь код, не прочитав соседние файлы - СТОП
- Не знаешь, какие файлы затронет задача - СТОП
- Начинаешь с реализации, а не с исследования - СТОП
- Нашёл в проекте похожее решение, но «напишу своё» - СТОП, используй существующее

## Экономия контекста

Не нужно читать ВСЁ. Стратегия:

1. `CLAUDE.md` - всегда (карта проекта)
2. Файлы в зоне задачи - обязательно
3. `ai-clone/feedback/` - если есть релевантные ошибки
4. `plans/` - если есть связанный план
5. Всё остальное - только по необходимости
